# 时间戳类排除字段白名单（封闭清单）

设计文档 §5.1 的口径是"**除时间戳类动态字段外无排除项**"。这份清单就是那唯一的
排除口子，`tests/golden_harness.py:check_golden(normalize=...)` 只允许处理下面列出的
字段。加一项需要一个理由，删一项会让基线更严（欢迎）。

| 字段 | 出现处 | 为什么必须排除 | 替代手段为什么不用 |
|---|---|---|---|
| `uptime_ms` | `/api/health` | `int((time.time() - _start_time) * 1000)`，只要进程真实跑过就有抖动 | 脚手架已把 `time.time` 冻结在 `FROZEN_NOW`，实测恒为 `0`；保留哨兵是为了**将来某处改用真实时钟时仍然可比较**，同时让"这个字段是时间派生的"这件事显式可见 |

## 不在白名单里、且永远不该进的

- `charge_event` 的 `start_time` / `end_time`（`%Y-%m-%d %H:%M:%S` 串）：由**调用方传入的
  时间戳**格式化，不是运行时刻。脚手架传定值，所以它是可逐字节比较的 —— 这正是
  "时间格式变了"这类回归的探测器（时区、补零、UTC vs 本地）。
- `session_id` / `sid`：数据库自增 id，脚手架用定值传入，不参与真实写入。
- `protocol_extend`、端口电压电流：设备状态，由 `snapshot_state()` 固定。
- SSE `keepalive` 行（`: keepalive\n\n`）：由 15s 超时触发，脚手架不等待那么久，
  因此不会出现在快照里；如果哪天它出现了，说明事件投递顺序变了。

## 判据

任何快照里出现"两次运行结果不同"的字段，先当作**缺陷**调查，确认无害才允许加进本表。
